HOW TO FIX GITHUB ACTIONS BUILD WARNINGS/FAILURES AFTER GITHUB UPGRADES
=======================================================================

Typical symptom (example, Nov 2026):
  "Node.js 20 is deprecated. The following actions target Node.js 20 but are
   being forced to run on Node.js 24: actions/checkout@v3, ruby/setup-ruby@<sha>"
GitHub periodically retires old Node runtimes for Actions. Old action versions
then warn, and eventually fail. The fix is to bump the actions to newer versions.

1. FIND WHICH REPO / WORKFLOW IS RUNNING
   - GitHub repo -> Actions tab -> click the failing/warning run -> note the
     workflow name (e.g. "Deploy Jekyll site to Pages").
   - Workflow files live in <repo>/.github/workflows/*.yml
   - Search them locally for the action named in the warning:
       grep -rn "uses:" .github/workflows
   - A repo can have several workflows; check all of them, not just one.
   - Note: if Settings -> Pages -> Source is "Deploy from a branch", GitHub runs
     its own built-in "pages build and deployment" workflow. You cannot edit
     that one; switch Source to "GitHub Actions" if you use your own workflow.

2. CHECK EACH ACTION'S RUNTIME (don't just bump to "the next version")
   A newer version is not always Node 24 (e.g. checkout@v4 is still node20,
   checkout@v5+ is node24). Check the "using:" line of the action's action.yml:
       curl -s https://raw.githubusercontent.com/<owner>/<repo>/<tag>/action.yml | grep "using:"
     e.g. .../actions/checkout/v6/action.yml
   Want "node24" (or "composite", which has no Node runtime of its own).
   Latest release of an action:
       curl -s https://api.github.com/repos/<owner>/<repo>/releases/latest | grep tag_name

3. EDIT THE WORKFLOW FILES
   Replace the old "uses:" versions. Versions that were verified as node24
   (Nov 2026):
     actions/checkout                  @v6
     actions/configure-pages           @v6
     actions/deploy-pages              @v5
     actions/upload-pages-artifact     @v4   (composite, fine)
     ruby/setup-ruby                   @v1   (floating tag, node24)
     docker/setup-qemu-action          @v4
     docker/setup-buildx-action        @v4
     docker/login-action               @v4
     docker/metadata-action            @v6
     docker/build-push-action          @v7
     JamesIves/github-pages-deploy-action @v4
   Tips:
   - Prefer a major tag (@v6) over an old pinned SHA like
     ruby/setup-ruby@55283cc... (v1.146.0), which is stuck on an old runtime.
   - Bump related actions together (configure-pages / upload-pages-artifact /
     deploy-pages) so their versions stay compatible.

4. COMMIT, PUSH, VERIFY
     git add .github/workflows
     git commit -m "Bump GitHub Actions to Node 24 versions"
     git push
   Then open the new run in the Actions tab and confirm the warning is gone.
   Re-run manually if needed: Actions -> workflow -> "Run workflow"
   (works only if the workflow has "workflow_dispatch:" under "on:").

5. IF THE BUILD STILL FAILS AFTER BUMPING
   - Read the failing step's log; a new action major version may have renamed
     inputs (check the action's README / release notes on GitHub).
   - Jekyll sites: ruby-version in setup-ruby may need to match the Gemfile
     (or a .ruby-version file); try bumping Ruby and run `bundle update` locally.
   - Temporary escape hatch (not a real fix): set env
     FORCE_JAVASCRIPT_ACTIONS_TO_NODE24=true (or ACTIONS_ALLOW_USE_UNSECURE_NODE_VERSION=true
     for old runtimes) on the job, then fix properly later.

HOW TO AVOID DUPLICATE POST URLS (post edits not showing up on the site)
------------------------------------------------------------------------
Permalink is /blog/:year/:title/ and :title comes from the FILENAME (the part
after YYYY-MM-DD-). Two posts in the same year with the same filename slug get
the SAME URL; Jekyll silently publishes only one and the other never appears
(edits to the hidden one look like they were "not deployed").
  - Give every post a unique slug within its year, e.g.
      2024-03-24-workshop-creative-writing.md
      2024-06-09-workshop-creative-writing-part2.md   (NOT the same slug)
  - Before adding a post, check for clashes:
      ls _posts | sed -E 's/^([0-9]{4})-[0-9]{2}-[0-9]{2}-/\1 /' | sort | uniq -d
    (no output = no clashes; same slug in different years is OK, same year is not)
  - Or override the URL in the post's front matter: permalink: /blog/my-unique-url/
  - Renaming a post changes its URL, so update any links to it
    (e.g. pages/writing.html in jasmine-zheng.github.io).

Reference:
  https://github.blog/changelog/2025-09-19-deprecation-of-node-20-on-github-actions-runners/

  - workshop-academy.github.io (.github/workflows/jekyll.yml, deploy.yml,
                                deploy-image.yml, deploy-docker-tag.yml)
